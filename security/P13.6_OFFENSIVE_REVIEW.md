# P13.6 — Revisión ofensiva controlada del frontend

Fecha: 2026-09-16  
Ámbito: CyberLibrary AI, frontend estático local.  
Autorización: revisión del proyecto propio solicitada por su responsable.  
Fuera de alcance en esta fase: Cloudflare, DNS, WAF, TLS público y pruebas contra terceros.

## Resumen ejecutivo

La revisión no ha identificado una vía explotable desde entrada de usuario para DOM XSS, ejecución dinámica de JavaScript, path traversal o open redirect externo en el frontend actual.

Se han encontrado cuatro puntos de defensa en profundidad que dependían de la integridad de datos locales. Se han endurecido para reducir el impacto de una manipulación futura de JSON o del índice de búsqueda:

1. El lector normativo valida que los enlaces de fuente sean HTTPS y pertenezcan a `eur-lex.europa.eu`.
2. El comparador normativo aplica la misma validación a los enlaces de fuente.
3. El buscador convierte las rutas del índice en rutas internas del mismo origen, evitando navegación protocol-relative si el índice fuese alterado.
4. Los catálogos de modelos y herramientas aceptan únicamente enlaces externos HTTPS.

## Pruebas realizadas

- Búsqueda de sinks DOM: `innerHTML`, `outerHTML`, `insertAdjacentHTML`, navegación dinámica y asignaciones de `href`.
- Búsqueda de primitivas peligrosas: `eval`, `new Function`, `document.write`, URLs `javascript:` y handlers HTML inline.
- Revisión de parámetros de URL y hash (`URLSearchParams`, `location.search`, `location.hash`).
- Revisión de redirecciones del catálogo de modelos.
- Revisión de datos locales que alimentan HTML dinámico y enlaces externos.
- Fuzzing lógico de esquemas y rutas con valores `javascript:`, `data:`, protocol-relative, traversal y URLs externas.
- Validación sintáctica de todos los JavaScript con `node --check`.
- Validación de referencias locales HTML/CSS/JS/imagen.

## Hallazgos

### [P13.6-001] BAJO — URL de fuente normativa confiada desde JSON local

**Estado:** CORREGIDO.  
**Archivos:** `js/observatorio-lector.js`, `js/observatorio-normativo.js`.

Antes, `source.html_url` se asignaba directamente a enlaces de la interfaz. No era controlable por una petición del visitante; requería modificar el JSON estático del despliegue. Aun así, una alteración de ese JSON podía introducir un esquema no deseado.

**Corrección:** solo se acepta `https:` con hostname exacto `eur-lex.europa.eu`; cualquier otro valor se neutraliza a `#`.

### [P13.6-002] BAJO — Índice de búsqueda confiado para construir destinos internos

**Estado:** CORREGIDO.  
**Archivo:** `js/search.js`.

Las rutas del índice eran tratadas como internas por contrato. Una entrada manipulada que comenzase por barras podía convertirse en una URL protocol-relative al construir el `href`.

**Corrección:** normalización explícita a una URL del mismo origen y devolución únicamente de `pathname + search + hash`.

### [P13.6-003] BAJO — Catálogos aceptaban HTTP además de HTTPS

**Estado:** CORREGIDO.  
**Archivos:** `js/models-catalog.js`, `js/ai-security-tools.js`.

No se han encontrado enlaces HTTP activos en los datos de catálogo actuales. Se elimina, no obstante, la posibilidad de navegación a una fuente externa sin TLS.

**Corrección:** solo se aceptan destinos `https:`; protocolos distintos se neutralizan a `#`.

### [P13.6-004] INFO — Sinks `innerHTML` existentes

**Estado:** ACEPTADO / CONTROLADO.

El proyecto usa `innerHTML` en varios componentes. En los puntos que reciben datos variables se aplica escape HTML, o bien los valores proceden de constantes/DOM local ya controlado. No se ha identificado un flujo desde entrada de usuario sin sanitización hasta ejecución HTML/JS.

No se recomienda reemplazar masivamente `innerHTML` en esta fase porque introduciría riesgo de regresión sin un beneficio proporcional. CSP se configurará posteriormente en Cloudflare como segunda barrera.

### [P13.6-005] INFO — Redirección de `modelos/detalle.html?id=`

**Estado:** SEGURO EN EL ÁMBITO REVISADO.

El parámetro se transforma a un slug alfanumérico y la redirección está fijada bajo `/modelos/fichas/`. No puede seleccionar protocolo, hostname ni ruta arbitraria externa.

## Resultado

No quedan hallazgos CRÍTICOS, ALTOS o MEDIOS en P13.6.

Riesgos residuales relevantes para las siguientes fases:

- La seguridad HTTP efectiva depende todavía de P13.2 en Cloudflare (CSP y cabeceras).
- La carpeta local `security/` es operativa y no debe formar parte del artefacto público de producción.
- Las pruebas de infraestructura pública, DNS, TLS, WAF, caché y exposición real se realizarán en la fase Cloudflare.
